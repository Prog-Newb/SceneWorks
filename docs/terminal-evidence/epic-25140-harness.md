## Ordinary product transport and ownership

The flat video DTO is submitted to **POST `/api/v1/video/jobs`**. Generic POST `/api/v1/jobs` is not the video route.

The adapter exports `protocol="epic-25140-physical-guard-v1"` and `acquire({manifest,backend,runDir})`; it must acquire/hold the existing combined Mac GPU/nax flock token or Windows selected-UUID exclusive OS lock, not a new independent file lock. `sourceFreeze.resourceContract[backend]` binds `{physicalGpuId,canonicalLocks}` to those exact established lock identities. The acquired live external guard exposes `{owned,ownerToken,lockIdentities,isOwnerAlive(),ownsCanonicalLocks(),beforePhase(phase),retainForOwnedJobs(intents),release()}`. `beforePhase` performs fresh existing driver/queue admission and returns `{phase,ownerToken,admitted,physicalGpuId,observedAt,queueObservedAt,conflictingJobs,driverSamples}`. These are outputs from the current verified actual guard adapter, not an opaque receipt supplied as a substitute. Wrong lock, unowned/dead owner, stale phase, conflicts or missing samples are refused. The external holder must retain ownership for all ambiguous/active owned intents until reconciliation/cancellation, even if this controller exits. `retainForOwnedJobs` handles that case; process exit alone must never free the physical token while a worker might still render.

`leasePath` is only an exclusive **campaign resume marker**. A dead marker owner may resume only its own exact campaign/run-directory/fingerprint; foreign/live markers are refused. It neither replaces nor claims the physical OS lock. The actual adapter is an outstanding integration requirement; CPU mocks only prove the driver refuses invalid guard observations.

Ambiguous transport reconciles via `/api/v1/jobs?projectId=...&limit=500`; absent, duplicate, changed or full-window results cannot justify resubmission because the API has no enqueue idempotency or complete history pagination.
